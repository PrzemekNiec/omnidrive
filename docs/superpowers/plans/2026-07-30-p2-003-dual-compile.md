# P2-003 Bin/lib dual-compile de-duplikacja — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sprawić, by 31 modułów crate’a `angeld` kompilowało się raz (w lib) zamiast dwa razy (lib + bin), przez przeniesienie 9 modułów bin-only do `lib.rs` i uczynienie `main.rs` konsumentem biblioteki `angeld`.

**Architecture:** `main.rs` przestaje deklarować jakiekolwiek `mod`; wszystkie moduły żyją w `lib.rs`. Bin referuje je jako `angeld::…`. `run_daemon` i bootstrap zostają w `main.rs`. Zmiana czysto strukturalna — zero zmian zachowania. Bezpiecznikiem jest istniejąca zielona suita testów + kompilator (nierozwiązana referencja = błąd budowania).

**Tech Stack:** Rust 2024, cargo workspace (`angeld` bin+lib, `omnidrive-core`, `omnidrive-cli`).

**Spec:** `docs/superpowers/specs/2026-07-30-p2-003-dual-compile-design.md`.

## Global Constraints

- **Zero zmian zachowania.** Wyłącznie relokacja deklaracji modułów i zmiana ścieżek referencji. Żadnej zmiany logiki, API sieciowego, schematu bazy.
- **Zero bumpu wersji.** Workspace zostaje na `0.3.28`.
- **Zakaz komentarzy w kodzie produkcyjnym** (CLAUDE.md §3).
- **Chirurgiczne zmiany** (CLAUDE.md §1) — tylko `angeld/src/lib.rs` i `angeld/src/main.rs`. Pliki 9 modułów bin-only NIE zmieniają treści ani lokalizacji.
- **Pre-push aktywny** (`fmt` + `clippy --workspace -D warnings`). Nigdy `--no-verify`.
- **Bramka przed commitem:** `cargo build --release --workspace` + `cargo clippy --workspace --all-targets -- -D warnings` + `cargo test -p omnidrive-core` + `cargo test -p angeld --lib` — wszystko zielone (baseline angeld **186**).
- **Jeden task = jeden commit.** Zakaz `--allow-empty`.

## Task 1: De-duplikacja bin/lib (A1)

To pojedynczy, atomowy refaktor — kroki są uporządkowane, ale kompilowalny stan powstaje dopiero po kroku 5. Cały task = jeden commit.

**Files:**
- Modify: `angeld/src/lib.rs`
- Modify: `angeld/src/main.rs`

**Interfaces:**
- Produces: `pub mod api; pub mod gc; pub mod repair; pub mod scrubber; pub mod sharing; pub mod shell_integration; pub mod shell_state; pub mod watcher; pub mod windows_hello;` dostępne jako `angeld::<moduł>` (parytet z 31 już eksportowanymi).
- Consumes: nic z wcześniejszych tasków (task samodzielny).

- [x] **Step 1: Baseline — potwierdź zieloną bramkę PRZED zmianą**

Run:
```bash
cargo build --release --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p omnidrive-core
cargo test -p angeld --lib
```
Expected: wszystko PASS; zanotuj liczbę testów angeld (baseline **186**). Jeśli cokolwiek czerwone PRZED zmianą — zatrzymaj się, to nie jest regresja z tego taska.

- [x] **Step 2: Dodaj 9 deklaracji modułów bin-only do `lib.rs`**

W `angeld/src/lib.rs`, po istniejących deklaracjach (zachowując porządek alfabetyczny tam gdzie to naturalne), dodaj:

```rust
pub mod api;
pub mod gc;
pub mod repair;
pub mod scrubber;
pub mod sharing;
pub mod shell_integration;
pub mod shell_state;
pub mod watcher;
pub mod windows_hello;
```

`windows_hello` **bez** atrybutu `cfg` (parytet z `main.rs`, gdzie też jest bez cfg). Pozostałe bez cfg. Na tym etapie moduły są zadeklarowane i w lib, i w main — kod nadal się kompiluje (podwójnie), to stan przejściowy.

- [x] **Step 3: Usuń WSZYSTKIE deklaracje `mod xxx;` z `main.rs`**

W `angeld/src/main.rs` usuń cały blok deklaracji modułów (linie z `mod acl;` do `mod windows_hello;` włącznie), w tym `mod win_acl;`, `#[cfg(target_os = "windows")] #[allow(dead_code)] mod win_session;` oraz `mod windows_hello;`. Po tym kroku `main.rs` nie deklaruje żadnego modułu. Kod przejściowo się NIE kompiluje (referencje `crate::…` w main jeszcze nie zamienione) — to naprawia krok 4.

- [x] **Step 4: Zamień `crate::` → `angeld::` w `main.rs`**

W `angeld/src/main.rs` zamień każde wystąpienie `crate::` na `angeld::` (blankietowo — zweryfikowano, że wszystkie `crate::<ident>` w main.rs to ścieżki modułów: `acl, api, api_error, auto_lock, autostart, aws_http, cache, cloud_guard, config, db, device_identity, diagnostics, disaster_recovery, downloader, gc, identity, ingest, lock_flow, logging, migrator, onboarding, packer, peer, pipe_server, recovery, repair, runtime_paths, scrubber, secure_fs, sharing, shell_integration, shell_state, smart_sync, uploader, vault, virtual_drive, watcher, win_acl, win_session, windows_hello`). Dotyczy zarówno `use crate::…` jak i inline `crate::…`.

- [x] **Step 5: Zbuduj; napraw ewentualne błędy widoczności/dead_code wskazane przez kompilator**

Run:
```bash
cargo build --release --workspace
```
Expected: PASS. Jeśli kompilator zgłosi:
- `module `X` is private` dla modułu, którego `main.rs` używa — podnieś w `lib.rs` `mod X;` → `pub mod X;` (przewidywane: żaden, bo `main.rs` nie używa `win_acl`/`win_session` poza deklaracją; ale zastosuj gdyby wystąpił).
- `dead_code` w `win_session` pod `-D warnings` (lib nie miała `#[allow(dead_code)]`, którą miał main) — dodaj `#[allow(dead_code)]` nad `pub mod win_session;` w `lib.rs`.

Wprowadź WYŁĄCZNIE poprawki wskazane przez kompilator/clippy, nic więcej.

- [x] **Step 6: Pełna bramka — potwierdź parytet z baseline**

Run:
```bash
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p omnidrive-core
cargo test -p angeld --lib
```
Expected: wszystko PASS, liczba testów angeld = baseline z kroku 1 (**186**). `clippy --all-targets` daje teraz jeden spójny set lintów (bin i lib to jedna kompilacja modułów).

- [x] **Step 7: Weryfikacja braku duplikacji + commit**

Weryfikacja, że żaden moduł nie jest zadeklarowany jednocześnie w obu plikach:
```bash
comm -12 <(grep -oE "mod [a-z_]+" angeld/src/main.rs | sort -u) <(grep -oE "mod [a-z_]+" angeld/src/lib.rs | sort -u)
```
Expected: pusty wynik (zero wspólnych deklaracji `mod`).

Commit:
```bash
git add angeld/src/lib.rs angeld/src/main.rs
git commit -m "refactor(angeld): P2-003 — bin konsumuje lib, koniec dual-compile 31 modułów"
```
